# Партнёрский кабинет на Timeweb Apps: запуск

Дата: 22.09.2026. Код: github.com/MakeBiz/partnersapp, ветка `main`. Пока Timeweb не проверен, кабинет продолжает жить на Vercel, домен переключаем последним.

## Что разворачиваем

Из **одного репозитория два приложения** Timeweb Apps (тип «Backend», Node.js 20, деплой из GitHub по пушу в `main`):

| Приложение | Команда сборки | Команда запуска | Зачем |
|---|---|---|---|
| `partners-web` | `npm ci && npm run build` | `npm start` | сайт: кабинет, админка `/admin`, вход, API |
| `partners-worker` | `npm ci` | `npm run worker:start` | очередь: партнёр в Битрикс, Telegram-группа, письмо |

`npm start` слушает порт из `PORT` (Timeweb задаёт сам). Воркер тоже отвечает на `PORT` (health-check: JSON с тем, что настроено). `worker:start` перед запуском применяет новые миграции базы, отдельно запускать миграции не нужно.

## Переменные окружения

Секреты вводятся **только в панели Timeweb** (Настройки приложения → Переменные). В чат, в репозиторий и в документы их не копировать.

| Переменная | web | worker | Значение |
|---|---|---|---|
| `DATABASE_URL` | да | да | база через PgBouncer, порт 6432 (как на Vercel) |
| `DIRECT_URL` | да | да | та же база в session-режиме, для миграций |
| `DB_CA_CERT` | желательно | желательно | CA сертификат базы (иначе шифрование без проверки сервера) |
| `APP_URL` | да | да | `https://partners.makebiztehnologies.com` (до переключения домена: адрес приложения Timeweb) |
| `GATEWAY_URL` | да | да | `https://agw.makebiztehnologies.com` |
| `GATEWAY_KEY` | да | да | ключ gateway (как на Vercel) |
| `APP_WEBHOOK_SECRET` | да | нет | секрет вебхуков ЮKassa и Битрикса (как на Vercel) |
| `ADMIN_BOOTSTRAP_LOGIN` | нет | да | логин Антона для первого входа, например `anton` |
| `ADMIN_BOOTSTRAP_PASSWORD` | нет | да | пароль для первого входа (после входа удалить переменную) |
| `ADMIN_BOOTSTRAP_TELEGRAM` | нет | да | ник Антона без @ |
| `TG_API_ID`, `TG_API_HASH` | нет | да | my.telegram.org → API development tools (шаг 4 плана) |
| `TG_SESSION` | нет | да | строка сессии личного аккаунта (шаг 4 плана) |
| `TG_BOT_USERNAME`, `TG_BOT_TOKEN` | нет | да | бот, который сидит в группах партнёров |
| `TG_TEAM_USERNAMES` | нет | да | кого добавлять в каждую группу, через запятую (ассистентка и др.) |
| `SMTP_URL`, `MAIL_FROM` | нет | да | почта для приглашений, например `smtps://…@smtp.timeweb.ru:465` |

Без `TG_*` и `SMTP_*` всё работает, просто соответствующий шаг в карточке партнёра будет «ошибка: не настроено», а ссылку-приглашение ассистентка копирует и отправляет сама. После настройки кнопка «Повторить» догоняет пропущенные шаги.

## Порядок запуска

1. **Доступ к базе.** Разрешить подключение из Timeweb Apps к базе 38.180.26.233 (порты 6432 и session-порт), если на сервере базы стоит фильтр по IP. Исходящие IP приложения видны в панели Timeweb.
2. **partners-worker.** Создать приложение, указать репозиторий и команды из таблицы, заполнить переменные (минимум: база, `APP_URL`, `GATEWAY_*`, `ADMIN_BOOTSTRAP_*`). После деплоя в логах должно быть «Применено миграций: N» (или «Новых миграций нет»), `bootstrap admin: {"created":"anton"…}` и `worker started`.
3. **partners-web.** Создать приложение, те же база, `APP_URL`, `GATEWAY_*`, `APP_WEBHOOK_SECRET`. Открыть `<адрес>/login`, войти логином и паролем из шага 2, попасть в `/admin`.
4. **Удалить `ADMIN_BOOTSTRAP_PASSWORD`** из переменных воркера. Ассистентку завести так же: поменять `ADMIN_BOOTSTRAP_LOGIN` на её логин, `ADMIN_BOOTSTRAP_ROLE=assistant`, задать пароль, перезапустить воркер, затем снова удалить пароль. Существующих пользователей бутстрап не трогает.
5. **Проверка.** Завести тестового партнёра в админке. Ожидаемо: запись в списке, ссылка-приглашение копируется, шаг «CRM» в ошибке «gateway не настроен» или в ожидании ответа gateway (пока Диспетчер не сделал `POST /partner`). Открыть ссылку-приглашение, задать пароль, войти партнёром.
6. **Домен.** Когда всё работает, переключить `partners.makebiztehnologies.com` с Vercel на `partners-web` в Timeweb, обновить `APP_URL` в обоих приложениях. Vercel оставить выключенным, но не удалять, пока не проработаем неделю.

## Шаг 4 плана: Telegram от личного аккаунта

Группу может создать только пользовательский аккаунт, поэтому воркер работает от аккаунта Антона. Для этого нужна строка сессии `TG_SESSION`: она даёт полный доступ к аккаунту, поэтому живёт **только** в секретах Timeweb.

Получение: разовый скрипт `npm run tg:login` (спрашивает телефон, код из Telegram и пароль 2FA, печатает строку). Для этого шага подготовлю файл с двойным кликом, который выполнит вход на Маке и положит строку в буфер обмена, чтобы Антон вставил её в Timeweb, не показывая никому.

Остальное для Telegram: создать бота у @BotFather (`TG_BOT_USERNAME`, `TG_BOT_TOKEN`), в `TG_TEAM_USERNAMES` перечислить ники команды. Если у партнёра закрыто добавление в группы, воркер отправит ему ссылку-приглашение в личку.
