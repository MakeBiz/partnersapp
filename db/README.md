# База данных партнёрского кабинета

Postgres на сервере 38.180.26.233, база `partners_cabinet`, доступ через PgBouncer (6432).

## Переменные окружения (Vercel)

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | приложение, transaction-пул |
| `DIRECT_URL` | миграции, session-пул |
| `DB_CA_CERT` | *(опционально)* CA-сертификат для полной проверки TLS |
| `DB_SSL=off` | *(только для локальных тестов)* отключить TLS |

Без `DB_CA_CERT` соединение шифруется, но подлинность сервера не проверяется (самоподписанный сертификат). Задать его — желательно.

## Зависимость

В `package.json` нужен пакет `pg`:

```
npm install pg
```

## Миграции

```bash
node db/migrate.mjs            # применить новые
node db/migrate.mjs --status   # что применено
```

Раннер идемпотентен: ведёт таблицу `schema_migrations`, каждый файл выполняется в транзакции, параллельные запуски разведены advisory-локом. Повторный запуск ничего не ломает.

Новая миграция — просто новый файл `000N_название.sql` в `db/migrations/`. Файлы применяются по алфавиту, уже применённые не трогаются. **Применённые файлы не редактировать** — только добавлять новые.

## Схема

14 таблиц:

- `partners` — партнёры и дерево приглашений (upline)
- `accounts`, `claim_codes` — способы входа и одноразовые коды привязки
- `admin_users`, `admin_audit` — админка и журнал действий
- `products`, `training_progress` — каталог и обучение
- `leads` — лиды из кабинета
- `clicks` — переходы по реф-ссылкам
- `commissions` — **леджер начислений** (ядро)
- `withdrawals`, `points_log`, `lead_exchange`, `settings`

### Что защищено на уровне базы

- **Дерево:** триггер `partners_upline_guard` запрещает самореферал и циклы (А→Б→А, в том числе через несколько звеньев), ограничивает глубину цепочки.
- **Леджер:** `UNIQUE (bitrix_deal_id, partner_id, level)` — пересчёт начислений идемпотентен, дубли невозможны.
- **Каскад:** строка уровня 2 ссылается на уровень 1 через `parent_commission_id ON DELETE CASCADE` — отмена уровня 1 снимает и уровень 2.
- **Диапазоны:** `pay_ratio` в (0;1], ставки 0–100, уровень только 1/2/3, статусы и источники — по списку.
- Деньги — `NUMERIC`, не float.

### Настройки вместо констант

Ставки и правила лежат в таблице `settings`, а не в коде: `commission.welcome_rate` (20), `commission.base_rate` (10), `commission.level2_rate` (10, **от комиссии** нижнего партнёра), `commission.level3_enabled` (false), `leads.lock_days` (60), коэффициенты выплат, баллы и пороги тиров.

Третий уровень включается флагом, без правки кода.

## Проверено

Миграции и ограничения прогонялись на настоящем Postgres: 16 функциональных тестов (защита дерева, идемпотентность леджера, каскадная отмена, суммы начислений welcome + уровень 2, ограничения лидов). Все пройдены.
